# AI Product Owner Agent - Copilot Context

## Project Overview

The AI Product Owner Agent is a production-ready VS Code extension that automates technical analysis for Jira epics and provides universal codebase analysis across multiple programming languages. It integrates with GitHub Copilot to generate comprehensive technical documentation through a role-based analysis workflow.

### Purpose
- Automate technical analysis of Jira epics
- Analyze codebases across 9+ programming languages (JavaScript, TypeScript, Python, Java, Go, C#, PHP, Ruby, Rust)
- Generate professional technical documentation
- Streamline product owner workflows with AI-assisted analysis
- Provide role-based analysis: Senior Product Manager → Principal Engineers → Product Owner

### Key Features
- 5-stage role-based analysis workflow
- Universal codebase pattern detection
- Jira API integration for epic analysis
- GitHub Copilot integration for enhanced analysis
- Automated documentation generation
- Context continuity between analysis stages

### Core Components Details

#### `MultiStageAnalysisEngine.ts`
- **Purpose**: Orchestrates the 5-stage role-based analysis workflow
- **Role-based Stages**:
  1. Senior Product Manager: Product Requirements Analysis
  2. Principal Engineer (Architecture): System Architecture Design
  3. Principal Engineer (Technical Design): Technical Design Specification
  4. Principal Engineer (Implementation): Implementation & Deployment Strategy
  5. Product Owner: Sprint Planning & Jira Epic Breakdown
- **Key Methods**: `runFullAnalysis()`, `executeSequentialStage()`, `generateTechnicalStagePrompt()`

#### `CodebaseAnalyzer.ts`
- **Purpose**: Universal codebase analysis across multiple programming languages
- **Capabilities**: Language detection, architectural pattern recognition, dependency analysis
- **Optimized**: 462 lines, efficient analysis with minimal overhead
- **Key Methods**: `analyzeCodebase()`, `detectLanguages()`, `identifyPatterns()`

#### `PromptTemplates.ts`
- **Purpose**: Contains role-based templates and orchestration logic
- **Templates**: 5 stage-specific templates with Context7 integration
- **Features**: Codebase context injection, previous stage context continuity
- **Key Exports**: `STAGE_1_PRODUCT_REQUIREMENTS_ANALYSIS`, `getRoleBasedTemplate()`

#### `JiraClient.ts`
- **Purpose**: Jira API integration for epic and project data
- **Authentication**: Supports multiple auth methods (API token, OAuth)
- **Key Methods**: `fetchEpic()`, `getProjectData()`, `authenticateUser()`

## Guidelines for Making Changes

### Before Making Changes
1. **Check Compilation**: Ensure `npm run compile` passes without warnings
2. **Run Tests**: Execute `npm test` to verify existing functionality
3. **Review Dependencies**: Check if new dependencies are necessary and justified
4. **Check for Duplicates**: Always verify files don't already exist before creating

### Development Workflow
1. **Atomic Changes**: Make small, focused changes that can be easily reviewed
2. **Test-Driven**: Write tests before implementing new features
3. **Error Handling**: Implement comprehensive error handling for all new code
4. **Documentation**: Update relevant documentation (README, CHANGELOG, etc.)

### Performance Considerations
- Limit file system operations to necessary files only
- Implement caching for expensive operations (codebase analysis, Jira API calls)
- Use async/await properly to avoid blocking the UI thread
- Dispose of all VS Code resources (output channels, status bar items, etc.)

### Security Guidelines
- Never log sensitive data (API tokens, user credentials)
- Sanitize all user inputs before processing
- Use VS Code secrets API for storing sensitive configuration
- Validate all external data (Jira API responses, file contents)

### Release Process
1. Update version in `package.json`
2. Update `CHANGELOG.md` with new features and fixes
3. Run full test suite
4. Package extension with `vsce package`
5. Test packaged extension in clean environment

### Common Issues to Avoid
- **Resource Leaks**: Always dispose of output channels and event listeners
- **Blocking Operations**: Use async/await for all I/O operations
- **Configuration Errors**: Always provide sensible defaults for configuration values
- **Error Swallowing**: Log and properly handle all errors
- **Memory Leaks**: Properly clean up event listeners and cached data

### Extension-Specific Best Practices
- Use workspace-relative paths whenever possible
- Handle cases where no workspace is open
- Respect user configuration and workspace settings
- Provide clear feedback for long-running operations
- Implement proper cancellation for user-initiated operations
